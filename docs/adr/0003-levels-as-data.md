# ADR 0003: Levels are TOML data, test expectations come from reference solutions

- Status: accepted

## Context

The project hopes to attract many people who can design puzzles but do not want to touch Rust.

## Decision

- One TOML file per level under `levels/<pack>/`, parsed with `serde` and `toml`, with
  `deny_unknown_fields` so typos are errors. TOML was chosen over RON and JSON for readable
  multi-line strings (stories, assembly) and comments.
- Hidden tests are generated by a small declarative generator DSL driven by a built-in PRNG
  (SplitMix64), so seeds give identical tests on every platform and release; hand-written edge cases
  are listed explicitly with expected outputs.
- The expected output of generated tests is computed by running the level's **reference solution**.
  To avoid a wrong reference silently defining the truth, levels need at least three hand-written
  cases with explicit outputs, and the repository cross-checks every shipped level against an
  independently written Rust oracle in the tests (`crates/algoclerk-levels/tests/oracles.rs`).
- Levels are embedded with `build.rs` + `include_str!`; desktop builds can also load packs from a
  user directory.

## Consequences

- Adding a puzzle is a data-only pull request; the validator and tests give fast feedback.
- Contributors who add levels are not forced to write a Rust oracle, but the maintainers may ask.
